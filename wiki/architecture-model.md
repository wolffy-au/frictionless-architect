## What this is

`architecture/model/` holds the **load-bearing subset** of the ArchiMate model
that was prototyped on branch `prototype-neo4j` — roughly 30 nodes "that stay
true regardless of how the platform's component boundaries finally land"
(`architecture/model/README.md:1-6`). It is **decomposition input** that feeds
the component split in [Architecture Overview](architecture.md), not the final
architecture.

The full prototype had **95 nodes / 143 relationships** across three ArchiMate
layers; the rest lives on tag `archive/prototype-neo4j` and is deliberately not
carried forward (`architecture/model/README.md:20-33`). Reasons for cutting:
stakeholders, SWOT assessments, goals, outcome metrics with placeholder numbers,
non-functional requirements, six "enabler" capabilities, business roles/objects,
and the KG value stream were "running ahead of the decisions" and should be
rebuilt inside each package's own spec when that package is real.

## Motivation layer

**Drivers** — why the platform exists (`architecture/model/nodes.yaml:16-35`):
market agility & competitive pressure, regulatory resiliency & social license,
systemic sustainability & complexity management, human-to-machine operational
scaling.

**Principles** — constitution-level (`architecture/model/nodes.yaml:40-59`):
Architecture as Executable Intelligence, Deterministic Human Accountability
("AI is advisory; the specification is deterministic; a human holds sign-off"),
Forensic Auditability, Policy as Code.

**Constraints** — the regulatory envelope every component inherits
(`architecture/model/nodes.yaml:64-88`): APRA CPS 230/234, Model Risk Management
Framework, Australian Privacy Act (APP), Cloud & Data Sovereignty Policy, and
Model Risk Standards (SR 11-7 / APRA).

**Functional requirements** — each one is a component contract
(`architecture/model/nodes.yaml:93-122`): automated spec generation from the
graph, automated regulatory-obligation mapping, pre-deployment compliance gate
enforcement, continuous as-built vs. as-designed reconciliation, and mandatory
human sign-off for non-standard changes.

## Business layer — process chain

Six processes (`architecture/model/nodes.yaml:161-191`) form an end-to-end
choreography (`architecture/model/relationships.yaml:38-58`):

```
Deterministic Spec Generation
  → Agentic Development Execution        (produces specification for)
  → Automated CICD Gate Execution        (submits artefacts to)
  → Production Release                    (gates and passes to)
  → Current State Discovery               (initiates discovery for)
  → Drift Review & Triage Gate            (surfaces findings for)
```

Drift review is human-gated: a Solution Architect approves architectural drift,
Security & Compliance approves regulatory drift, and only validated findings
enter the delivery pipeline (`architecture/model/nodes.yaml:186-191`).
