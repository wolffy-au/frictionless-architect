## What it is

`digital-twin-knowledge-graph` is subsystem 3 of the platform
(`platform/packages/digital-twin-knowledge-graph/README.md`): the knowledge-graph
read path (`if-twin-read-path`, GH #106) over the Neo4j-backed ArchiMate model,
plus the ArchiMate exchange-format parser and idempotent schema/ingestion
manager it is built on. It is modelled as `art-pkg-digital-twin-knowledge-graph`
in `architecture/model/`, realising the package. It is a **library, not a
service** — no FastAPI app, router or CLI entrypoint; it is consumed as an
ordinary Poetry path dependency ([ADR-0005](decision-log.md)) (`platform/packages/digital-twin-knowledge-graph/README.md`).

## Scope boundary: intent plane only

`sub-twin` is modelled with two planes: an **intent plane** (the ArchiMate
architecture model itself) and a **current-state twin plane** (built by
`fn-twin-ingest` from live infrastructure/deployment data). This package
implements only the intent-plane read/ingest path — exactly what today's flat
`src/` `data_loader.py`/`sample_parser.py`/`schema/manager.py` already do.
`fn-twin-ingest` (current-state twin ingestion) and `fn-ledger-record` (the
forensic ledger, presently backed by `controls-compliance-catalog`'s own
append-only ledger file) are both explicitly out of scope for this increment
(`platform/packages/digital-twin-knowledge-graph/specs/001-knowledge-graph-read-path/spec.md` §"Scope boundary", §Assumptions).

Within the intent plane, only one of two ingestion paths `architecture/model/README.md`
and ADR-0007 anticipate is covered: ArchiMate Exchange Format files in, via
`SampleParser`. ADR-0007's `[later]` "Neo4j seed" — reading `architecture/model/`'s
own canonical YAML directly into Neo4j, bypassing the Exchange-XML parser — is
out of scope here too; no code anywhere does this today
(`platform/packages/digital-twin-knowledge-graph/specs/001-knowledge-graph-read-path/spec.md` §Assumptions).

It does **not** yet replace flat-`src/`'s `visualizer/api.py` or
`scripts/neo4j_schema.py` — those keep their own, unchanged copies of the read
path, parser and schema manager until the visualiser API/UI split
(`ARCHITECTURE.md` §8.2, step 7) or a dedicated follow-up cuts them over
(`platform/packages/digital-twin-knowledge-graph/README.md` §"Scope boundary"). The package's first real, permanent consumer
is instead [Conversational Model Authoring](modelling-specification.md), which
calls `KnowledgeGraphReadPath(GraphSettings()).collect()` as an ordinary
function call (`platform/packages/digital-twin-knowledge-graph/specs/001-knowledge-graph-read-path/contracts/read-path.md`
§"Consumer compatibility note").

## Public surface

```python
from digital_twin_knowledge_graph import (
    GraphSettings,
    KnowledgeGraphReadPath,
    ReadPathError,
    SampleParser,
    ParsedSample,
    SchemaManager,
)
```

Three pieces (`src/digital_twin_knowledge_graph/*.py`;
`platform/packages/digital-twin-knowledge-graph/specs/001-knowledge-graph-read-path/contracts/read-path.md`):

- **`KnowledgeGraphReadPath(settings).collect()`** — returns
  `{"elements": [...], "relationships": [...], "views": [...]}` as plain data;
  no `neo4j` driver, session or record type crosses this interface. Returns
  empty collections when no graph connection is configured, and raises the
  package's own `ReadPathError` (never a raw `neo4j`/`Neo4jError` type, chained
  via `raise ... from exc`) on an unreachable graph or failed query.
- **`SampleParser(sample_file).parse()`** — normalizes an ArchiMate 3 Exchange
  Format file into a `ParsedSample` (elements, relationships, views, warnings)
  with no graph connection involved. Rejects a file with no root element or
  the wrong ArchiMate namespace with a specific error
  (`FileNotFoundError`/`ParseError`/`ValueError`/`ArchimateNamespaceError`);
  a duplicate element, relationship or view identifier keeps the last
  definition and is recorded as a warning rather than failing.
- **`SchemaManager(uri, user, password)`** — `apply_constraints()`,
  `ingest(payload)` (idempotent merge of elements/relationships/views/diagrams;
  raises `ValueError` naming the missing endpoint(s) if a relationship's
  source/target isn't present, rather than creating a dangling edge),
  `run_audit_checks()` (dangling view/diagram references, views with no
  members), and `record_schema_version(name)`.

## The spec (`001-knowledge-graph-read-path`)

Drafted 2026-10-12 against GH #106 (ADR-0005 for scope/sequencing, ADR-0006 for
"port ideas from `prototype-neo4j`, never merge it wholesale", ADR-0007 for the
deferred direct-YAML seed path, ADR-0017 for the still-open ontology question).
Five user stories (`platform/packages/digital-twin-knowledge-graph/specs/001-knowledge-graph-read-path/spec.md` §"User Scenarios"):

1. **Query the graph without touching Neo4j directly (P1)** — the interface the
   model already names, and the one piece every downstream migration step is
   blocked on.
2. **Parse an exchange file independently of the graph (P1)** — the input side
   of ingestion, and what the visualiser's merge of live-graph and sample data
   already depends on.
3. **Ingest a model into the graph idempotently (P2)** — re-ingesting the same
   model leaves node/edge counts unchanged.
4. **Depend on the package as an in-process library, not a service (P2)** — no
   HTTP router or wire format until a second consumer forces a service
   boundary (ADR-0005).
5. **Build the new code equivalent to today's flat-`src/` behavior (P2)** —
   built and tested against the existing `data_loader`/`sample_parser`/
   schema-manager test cases, with flat-`src/` itself untouched.

15 functional requirements and 6 success criteria follow directly from these
(`platform/packages/digital-twin-knowledge-graph/specs/001-knowledge-graph-read-path/spec.md` §Requirements, §"Success Criteria").
FR-012 is explicit that repointing flat-`src/`'s callers onto this package, and
retiring the flat originals, is **out of scope** for this increment.

### Design decisions (research)

Phase 0 research records seven decisions
(`platform/packages/digital-twin-knowledge-graph/specs/001-knowledge-graph-read-path/research.md`):

- **R1 — plain library.** A `KnowledgeGraphReadPath` class plus `ReadPathError`
  in `digital_twin_knowledge_graph.read_path`; no FastAPI app, router or CLI,
  because ADR-0005 defers an HTTP boundary until a second consumer needs one.
- **R2 — build fresh, don't cut over.** The four modules (`read_path`,
  `sample_parser`, `schema_manager`, `namespaces`) are new, with flat-`src/`
  as reference behaviour. The root and `platform/` are separate Poetry
  projects with separate lockfiles, and no ADR documents how a root consumer
  would depend on a `platform/packages/*` path, so full or partial cutover was
  rejected for this increment.
- **R3 — no driver-type leakage.** All `neo4j` imports are confined to
  `read_path.py` and `schema_manager.py`; public calls return plain data or
  raise `ReadPathError`.
- **R4 — selective port from `prototype-neo4j`.** Only the ArchiMate
  business/motivation vocabulary and the batched `UNWIND`-style ingestion are
  ported (attributed to ADR-0006). The forensic ledger stays with
  `controls-compliance-catalog`, and cherry-picking from the archive tag was
  rejected.
- **R5 — rename.** `DataLoader` becomes `KnowledgeGraphReadPath` and
  `DataLoaderError` becomes `ReadPathError`, to match the model's
  `if-twin-read-path` name. `SampleParser` and `SchemaManager` keep theirs.
- **R6 — settings.** `GraphSettings(BaseSettings)` in the package's own
  `config.py` reads `neo4j_uri`/`neo4j_user`/`neo4j_password` under the
  existing `FRICTIONLESS_ARCHITECT_` prefix, so operators configure Neo4j once.
- **R7 — tests.** The flat-`src/` unit tests are ported with unchanged
  assertions, plus the one integration test needing a real Neo4j.
