## Revisions and implementation notes

The **P** rows (0017–0019) exist because `specs/EPIC-001-governance-platform`
deliberately de-specified premature product choices — persistence technologies,
the authorization model and policy language, the ADR cryptographic scheme,
accepted serialization formats, and the API error wire format are all listed
there as "deferred solution decisions" to be re-decided intentionally
(`specs/EPIC-001-governance-platform/spec.md` §"Deferred solution decisions"; see ADR-0027 and the later rows are on [ADR-0020–0029](decision-log-ui-visualiser-model.md) and [ADR-0030 onward](decision-log-0030-onward.md).

ADR-0004 gained a clarifying note that `003-gh-roadmap-archimate` (added
2026-10-05) continues the same flat, un-migrated `NNN-` numbering as the
other pre-migration specs rather than starting a new numbering instance
(`docs/adr/0004-two-tier-spec-numbering.md`).

ADR-0010 was **revised in place** on 2026-09-26 (GH #65) to cover a second
kind of load-bearing content: the model now also carries the platform's own
**packaging and migration** (section E) — code packages as Artifacts realising
the six subsystems, the `ARCHITECTURE.md` §8 restructure steps as Work
Packages, and the platform's Plateaus (originally hand-authored Baseline / Transition / Target; since ADR-0035 generated from the GitHub roadmap). These are
load-bearing in the same sense as the motivation/strategy/business skeleton:
ADR-0005's package-dependency ordering and the §8 step sequence are decided
*against* this section, not the other way around, and it is kept to what
§3.2/§8 already commit to — infrastructure (Nodes, SystemSoftware) waits on
#55's open decisions (`docs/adr/0010-load-bearing-skeleton-only.md`). ADR-0005
itself was revised the same day (GH #60): it had originally named the
visualiser API/UI split as the first extraction, but that split needs
`digital-twin-knowledge-graph` as a library and that package isn't scaffolded
until §8 step 4, so the split couldn't go first. `controls-compliance-catalog`
(the policy-to-OSCAL pipeline, GH #44) has no knowledge-graph dependency, so it
takes the first-extraction slot instead and the visualiser split moves to step
7 — see [Architecture Overview](architecture.md) §"Migration sequence". See
[Architecture Model](architecture-model.md) §"Packaging and migration".

ADR-0012 clarifies that the ADR log's own `Status` field lifecycle
(`Proposed|Accepted|Superseded by ADR-NNNN|Deprecated`, per
`docs/adr/0000-adr-template.md`) is **analogous, not identical** to the
governed-entity FSM (`Draft→Under Review→Approved→Superseded`) ADR-0026
gives action-based endpoints: `Proposed` covers both `Draft` and
`Under Review`, `Accepted` is roughly `Approved`, `Superseded` maps directly,
and `Deprecated` has no FSM equivalent at all
(`docs/adr/0012-adr-as-attested-fsm.md`).

ADR-0016 was extended on 2026-10-04 (constitution Principle X, commits
`1a7408d`/`491d8e7`): a `speckit-plan` must now state its own **model
impact** — the element/relationship/view ids it adds, changes or retires in
`architecture/model/`, or "none" — with `tasks.md` carrying the matching
edits plus `validate.py`/diagram-regeneration tasks. The traceability record
for that model-impact statement lives in the constitution's own Sync Impact
Report, not in a new ADR
(`docs/adr/0016-every-change-linked-to-an-adr.md`). See
[Governance & Constitution](governance-and-constitution.md).

ADR-0018 was **updated in place** on 2026-09-27 (GH #55) to resolve "local
compose only, or a hosted cluster?" as a **phased** answer rather than a
single choice: `orchestration/compose/` stays the runtime through the MVP
milestone (ADR-0024), then the data layer moves to a hosted cluster for
target architecture. The hosted cluster's own shape — managed vs.
self-managed, which orchestrator — is deliberately left to a follow-up ADR;
nothing in the codebase argues for one option yet. The architecture model
carries this as Plateaus `plat-policy-to-oscal-mvp-1` → `plat-multi-user-collaboration-2` with
`gap-policy-to-oscal-mvp-to-multi-user-collaboration` between them (it was a hand-authored
`plat-runtime-mvp`/`plat-runtime-target`/`gap-runtime-hosted` set until the ADR-0035 cut-over), shown in
its own `view-runtime-migration` rather than the §8 packaging view — a different transition story. See
[Architecture Model](architecture-model.md).

The `adr-auditor` agent sweeps for decisions made without a record and for ADRs
that have drifted — see [Agent Skills & Workflows](agent-workflows.md).
