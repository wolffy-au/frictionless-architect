## Resolving conflicts between documents

"No document automatically wins a conflict." When two documents — or a
document and the code or model — disagree, the rule is
(§"Resolving Conflicts Between Documents"):

1. **Stop** — don't build on either side.
2. **Find the root cause**: which decision was made, where it was recorded, and
   which documents failed to follow it.
3. **Get a final answer** from the maintainer before changing anything.
4. **Fix every affected document**, and file or amend an ADR when the answer is
   load-bearing.

## Core principles

From §"Core Principles":

| # | Principle | Thrust |

| I | Code Quality | Self-documenting, modular, SOLID, DRY; functions under ~30 lines; no magic numbers |

| IX | Cross-Platform Consistency | Equivalent behaviour and data fidelity across platforms; graceful degradation |

### Principle X in practice

Principle X is new in 1.2.0 (§"X. Decision Traceability & Documentation
Integrity"):

- Any load-bearing choice gets an ADR under `docs/adr/`, from
  `0000-adr-template.md`.
- An Accepted ADR must be reflected in `ARCHITECTURE.md` and
  `architecture/model/` **in the same PR**. If that isn't possible, open a
  tracking issue and mark the ADR **A\*** ("accepted, not yet reflected") in the
  `docs/adr/README.md` index until it is.
- Diagrams are generated from `architecture/model/`, never hand-edited; the
  wiki is derived and never a source.

## Development workflow

Six stages (§"Development Workflow"):

1. **Specify** (`speckit-specify`)
2. **Plan** (`speckit-plan`)
3. **Record** — file or update an ADR for every load-bearing choice the plan
   makes (Principle X)
4. **Break down** (`speckit-tasks`)
5. **Implement** (`speckit-implement`), Red-Green-Refactor
6. **Verify** — `scripts/pre_commit_checks.sh` on every commit,
   `scripts/pre_merge_checks.sh` before merge

See the `speckit-*` skills in [Agent Skills & Workflows](agent-workflows.md).

## Quality gates

Before a feature is "Done" (§"Quality Gates"):

- **Linting & formatting**: `ruff`, `pyright`, `mypy`, `pymarkdown`.
- **Test suite** (pytest and behave) passes after every user story.
- **Coverage** ≥ 90% (Principle II).
- **Commit messages** follow Conventional Commits, enforced by commitizen
  (ADR-0025).
- **Documentation & decisions**: docs updated; load-bearing choices have an
  ADR; `ARCHITECTURE.md` and the model agree with the ADR log.
- **Constitution Check** against the core principles.

## Governance of the constitution itself

Amendments go via PR with a rationale; versioning is semantic; principle
numbers are globally unique and never reused; deviations must be justified in
the relevant `plan.md` complexity-tracking section (§"Governance").
