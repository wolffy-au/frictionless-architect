## What it is

`llm-provider-config` is a shared package under `platform/packages/`, not one of
the six subsystems: it resolves which LLM provider, model, parameters and credential
a given call uses, as a thin layer over `litellm` (`platform/packages/llm-provider-config/README.md`). It was decided in
ADR-0034, which also sets the general rule that a capability needed by more than one
subsystem gets its own named sibling package rather than a catch-all `common`
(`docs/adr/0034-shared-packages-and-llm-provider-config.md` §Decision). It is still
`version = "0.0.0"`, Python `>=3.11,<3.14`, and has no feature specs of its own yet
(`pyproject.toml`; `platform/packages/llm-provider-config/specs/README.md`). Its first consumer is
[Controls & Compliance Catalog](controls-compliance-catalog.md); see
[Architecture Overview](architecture.md) for where shared packages sit.

## Providers

Day-one providers are OpenAI, Google Gemini, Anthropic Claude, Ollama and GitHub
Copilot. `Provider` is a string enum, and `platform/packages/llm-provider-config/src/llm_provider_config/resolve.py` maps each to a `litellm` model
prefix: `openai/`, `gemini/`, `anthropic/`, `ollama_chat/` and `github_copilot/`
(`src/llm_provider_config/settings.py`, `platform/packages/llm-provider-config/src/llm_provider_config/resolve.py`). Ollama defaults its `api_base`
to `http://localhost:11434` when none is set (`platform/packages/llm-provider-config/src/llm_provider_config/resolve.py`).

Two providers are *keyless* (`KEYLESS_PROVIDERS` in `platform/packages/llm-provider-config/src/llm_provider_config/settings.py`): Ollama is local,
and GitHub Copilot signs in through GitHub's device flow on first use, with `litellm`
caching the token under `~/.config/litellm/github_copilot/` — so sign in once from a
terminal before using it from the UI, since the first call blocks on an interactive
prompt (`README.md`). The settings page shows no key field for either, and the key
endpoint answers `422` (`platform/packages/llm-provider-config/src/llm_provider_config/router.py`).

## Settings model

Settings are a Pydantic model: an optional global `default` plus a `components` map of
per-component overrides keyed by a component id the consuming package declares, for
example `controls-compliance-catalog.candidate-conversion`. Resolution is "override if
present, else default" with no deeper chain, and raises `NotConfiguredError` when
neither exists (`platform/packages/llm-provider-config/src/llm_provider_config/settings.py`; ADR-0034 §Decision). Each entry names a provider and
model and may carry `params`, an `api_base`, and a `credential_ref` (the keyring entry
name, defaulting to the provider name). Unknown fields are rejected
(`platform/packages/llm-provider-config/src/llm_provider_config/settings.py`).

They are stored in `~/.config/frictionless-architect/llm.toml`, outside the repo tree;
`LLM_PROVIDER_CONFIG_PATH` overrides the location. A `[default]` table plus optional
`[components."<id>"]` tables hold no key, only the reference (`README.md`; `platform/packages/llm-provider-config/src/llm_provider_config/store.py`).
`save_settings` tries `chmod 0o600` and suppresses `OSError` (via `contextlib.suppress`) on mounts that refuse it
(`platform/packages/llm-provider-config/src/llm_provider_config/store.py`).

## Credentials

Keys never go in a repo file or `.env`. `get_api_key` looks in the OS keychain through
`keyring` (macOS Keychain, Windows Credential Manager, Linux Secret Service), and
falls back to the provider's conventional environment variable (`OPENAI_API_KEY`,
`GEMINI_API_KEY`, `ANTHROPIC_API_KEY`) as a plaintext escape hatch with a logged
warning; if neither has a key it raises `MissingCredentialError`
(`platform/packages/llm-provider-config/src/llm_provider_config/credentials.py`). ADR-0034's "Implementation status" records this fallback as an
amendment to the original keychain-only decision, to make headless CI and
devcontainers workable. `key_source` reports only `not-needed`, `keychain`,
`environment` or `missing`, never the key (`platform/packages/llm-provider-config/src/llm_provider_config/credentials.py`).

## Using it

`resolve_call(component)` returns a `ResolvedCall` whose `completion_kwargs()` are
passed straight to `litellm.completion` — the package does not wrap `litellm`'s call
surface (`README.md`; `platform/packages/llm-provider-config/src/llm_provider_config/resolve.py`).

## The settings router

`create_settings_router([Component(id=..., label=...)], prefix="/settings/llm")`
returns a FastAPI router a subsystem UI mounts, in line with ADR-0020's rule of no
central dashboard (`platform/packages/llm-provider-config/src/llm_provider_config/router.py`; ADR-0034 §Decision). It serves an HTML page at the
prefix and a JSON API under it (`platform/packages/llm-provider-config/src/llm_provider_config/router.py`):

- `GET /state` — config path, providers (with `needs_key`), the default, and each
  component's override.
- `PUT /default`, and `PUT`/`DELETE /components/{id}` — edit settings; unknown
  components give `404`.
- `PUT`/`DELETE /keys/{provider}` — write to the keychain; `503` with an
  environment-variable hint where there is no keychain, `422` for keyless providers,
  and `404` when `DELETE` finds no stored key.
- `POST /test` — "Test connection": a one-word completion, returning `{ok, message}`;
  `404` for an unknown component.

Each of these non-2xx outcomes is declared in the route's `responses=`, so the
mounted app's OpenAPI document lists them (`router.py:94`, `101`, `113-117`, `131`, `141`).

The page edits the global default, API keys and per-component overrides; keys are
never returned. There is no authentication — the single-user local MVP of ADR-0024
— so the server should bind to localhost (`README.md`). `controls-compliance-catalog`
mounts it at `/settings/llm` and its playground links to it.

## Development

From `platform/`: `poetry install`, then `poetry run pytest
packages/llm-provider-config/tests`; `bash scripts/platform_checks.sh` runs the full
gate (`README.md`). Tests use a fake `litellm.completion` and an in-memory keyring; an
opt-in live check against a local Ollama is gated by `RUN_OLLAMA_TESTS=1` (ADR-0034
§Implementation status).
