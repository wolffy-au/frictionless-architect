`third_party/it4it` is a git submodule — [`wolffy-au/frictionless-it4it`](https://github.com/wolffy-au/frictionless-it4it)
— holding a hand-authored transcription of the Open Group's IT4IT 3.0
value-stream reference model, vendored per [ADR-0029](architecture.md). It
is **not an official Open Group artifact** (`third_party/it4it/README.md`).
This page covers the vendored repo's own content; how it's consumed —
merged into the platform's own model, the touchpoint bridges that stay
first-party — is covered in [Architecture Model](architecture-model.md)
§"D. IT4IT alignment".

## Schema

Same authoring convention as this repo's own `architecture/model/`: plain
YAML lists of `{type, id, name, desc?, props?}` elements and
`{type, source, target, label?, props?}` relationships, projected the same
way by a consumer's `build.py` (`third_party/it4it/README.md`). Every
element/relationship `id` carries an `it4it-` prefix, which is what keeps
the merged id space collision-free when a consuming project hashes it
alongside its own content via `det_id()`/`NS` — there is no separate
ID-reconciliation step (`third_party/it4it/elements.yaml:1-9`).

## Contents

**142 elements**: 42 `Capability`, 36 `ValueStream` (the root wrapper, its 7
streams, and 28 stages), 36 `Outcome`, 24 `Stakeholder`, and 4 `Grouping`
(the canonical value-stream domains — below)
(`third_party/it4it/elements.yaml`).

- **Value-stream skeleton** — a root `ValueStream` ("IT4IT: Value Streams")
  composing the 7 streams (Explore, Evaluate, Integrate, Deploy, Release,
  Operate, Consume), each in turn composing its own stages (28 total). The
  streams form a **`Flow` network, not a linear pipeline** — several stream
  pairs flow both ways in the source model, preserved as-is, not treated as
  a modelling error (`third_party/it4it/relationships.yaml` §"Stream-to-
  stream network").
- **42 capabilities** grouped into 4 canonical domains via `Aggregation`
  (`Grouping` elements, exempt from ArchiMate viewpoint filtering so they
  render safely alongside the strict capability/outcome allow-list on the
  Capability Map view): Strategy to Portfolio, Requirement to Deploy,
  Request to Fulfill, Detect to Correct
  (`third_party/it4it/elements.yaml:778-810`).
- **36 outcomes**, each `Realization`-linked from the value stream that
  delivers it — plus the root's own realization of "IT4IT: Digital
  Product" (`third_party/it4it/relationships.yaml`).
- **24 stakeholder roles**, carried as a catalog — the source model has no
  `Driver`/`Assessment` elements to connect them to.

## Relationships

**235 relationships**: 112 `Serving`, 36 `Realization`, 35 `Composition`,
34 `Aggregation`, 18 `Flow` (`third_party/it4it/relationships.yaml`). All
112 `Serving` edges are **derived**, not verbatim from the source: they
collapse the source model's own longer chain
(`DataObject --Realization--> Stage`; `DataObject --Realization--> Resource`;
`Resource --Assignment--> Capability`) into a single
`Capability --Serving--> Stage` edge per reachable pair — `Serving` chosen
as the weakest/most-representative type in that chain, matching the
capability-serves-stage convention a consuming project's own model uses
elsewhere. Marked `<<derived>>` / `props: {derived: "true"}` so they're
distinguishable from the source-verbatim `Composition`/`Realization`/`Flow`
edges (`third_party/it4it/relationships.yaml` §"Derived: Capability
--Serving--> Stage"). No bridge relationships to any consuming project's
own elements live here — that touchpoint layer belongs in the consumer,
referencing these ids directly (`third_party/it4it/relationships.yaml:1-10`).

## Views

4 views, one per standard ArchiMate viewpoint, each scoped to only this

| IT4IT: Stakeholder | `stakeholder` | 24 | The 24 stakeholder roles, as a catalog |
| IT4IT: Outcome Realization | `outcome_realization` | 44 | The 7 streams (plus root) and the 36 outcomes they realize |

An earlier "IT4IT Alignment" monolith view (79 elements, everything at
once) predated this 4-view split and was dropped once fully superseded —
see [Architecture Model](architecture-model.md) §"IT4IT reference views".

## Diagrams

Each view's `diagram:` key resolves to `diagrams/vision/<name>.puml`/`.svg`
in this repo — the same `vision/` bucket a consuming project uses for its
own stakeholder/capability-map/value-stream/outcome-realization diagrams,
rendered by that consumer's `render_diagrams.py` (this repo carries no
build tooling of its own; see [Architecture Model](architecture-model.md)
§"D. IT4IT alignment" for how a consumer wires that up).
