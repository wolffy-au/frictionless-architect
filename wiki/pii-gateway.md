## What it is

`pii-gateway` is a shared package under `platform/packages/`, not one of the six
subsystems. It scrubs PII/PHI from content before that content reaches an LLM provider
(`platform/packages/pii-gateway/README.md:3-5`). ADR-0014 makes the scrubbing mandatory,
and ADR-0043 chooses the engine. It is a sibling of
[LLM Provider Configuration](llm-provider-config.md) rather than part of it, because
ADR-0034 separates *which provider* from *what content*
(`docs/adr/0014-pii-anonymization-gateway.md` §Consequences). It is still
`version = "0.0.0"`, Python `>=3.11,<3.14`, and has one feature spec, whose 35 tasks are
all ticked although `spec.md` still says Draft
(`platform/packages/pii-gateway/pyproject.toml:1-7`;
`platform/packages/pii-gateway/specs/001-pii-gateway/spec.md` header;
`platform/packages/pii-gateway/specs/001-pii-gateway/tasks.md`).

Consumers take it as a path dependency. ADR-0014 treats that as a build-time dependency,
so the model has no per-consumer Serving edge
(`docs/adr/0014-pii-anonymization-gateway.md` §Consequences;
`platform/packages/modelling-specification/pyproject.toml:17`).

## The scrub contract

`scrub(text, *, context) -> ScrubResult` is the one call surface. Each call loads the
config, runs the detectors, drops matches in inactive categories, and then takes one of
three outcomes (`platform/packages/pii-gateway/src/pii_gateway/scrub.py:56-118`):

| Outcome | When | `text` returned |
| --- | --- | --- |
| `passed_through_unchanged` | No active match | The input, byte for byte |
| `redacted_and_proceeded` | Match, default failure-mode | Spans replaced with `<CATEGORY>` |
| `flagged_for_review` | Match, flag-for-review failure-mode | The input, with `pending_confirmation` set |

Those are the only three states
(`platform/packages/pii-gateway/src/pii_gateway/models.py:33-38`;
`platform/packages/pii-gateway/specs/001-pii-gateway/data-model.md` §`ScrubResult`).
A span that matches two categories yields one `Match` per category at the same location
(`platform/packages/pii-gateway/src/pii_gateway/models.py:49-61`).

`scrub()` is synchronous. The plan justifies its 2-second ceiling (SC-005) against the
constitution's 200ms rule: every call site is already synchronous, and the cost is small
next to the LLM call it gates. A unit test asserts the ceiling for each known context
(`platform/packages/pii-gateway/specs/001-pii-gateway/plan.md` §Constitution Check;
`platform/packages/pii-gateway/tests/unit/test_scrub.py:114-122`).

## Why the failure-mode differs by context

ADR-0014 picks the default by whether a human is present. Unattended drafting paths
auto-redact, because a block would stall on any false positive and a review flag would
have nobody to go to. The conversational agent flags for review, because the architect
is already in that turn and can simply be asked. Neither default is a hard block
(`docs/adr/0014-pii-anonymization-gateway.md` §Decision, §Alternatives considered).

Three contexts are registered: `spec-generator`, `governance-eval` and
`conversational-authoring`. Only the last seeds `flagged_for_review`. An unrecognised
context gets the global auto-redact default
(`platform/packages/pii-gateway/src/pii_gateway/config.py:28`,
`platform/packages/pii-gateway/src/pii_gateway/config.py:48-56`,
`platform/packages/pii-gateway/src/pii_gateway/config.py:85-94`).

### Reviewing a flagged match

`PendingConfirmation.resolve()` returns the redacted text for `REDACT` and the original
for `ALLOW` and `EDIT` -- except `ALLOW` on the synthetic engine-error match (see
[Failing closed](#failing-closed) below), which it refuses instead
(`platform/packages/pii-gateway/src/pii_gateway/models.py:93-113`). So `EDIT` is not a
complete operation in the gateway: the caller has to supply the replacement.
`modelling-specification` does that by re-scrubbing the architect's `edited_text` under
the same context, so a still-sensitive edit is flagged again rather than sent
(`platform/packages/modelling-specification/src/modelling_specification/router.py:431-439`;
`platform/packages/modelling-specification/src/modelling_specification/authoring/delta.py:318-334`).

The confirmation has no timeout and no stored form. An abandoned turn just discards it
(`platform/packages/pii-gateway/specs/001-pii-gateway/spec.md` §Clarifications). In
`modelling-specification` it sits on the in-memory session between `propose` and
`propose/resolve-pii`, which is the one place it outlives a single `scrub()` call
(`platform/packages/modelling-specification/src/modelling_specification/authoring/state.py:94-99`).
A flagged response carries the matches and makes no LLM call
(`platform/packages/modelling-specification/src/modelling_specification/router.py:191-208`,
`platform/packages/modelling-specification/src/modelling_specification/router.py:337-340`).

## Detection

Presidio supplies the recognizers and the anonymizer over spaCy's `en_core_web_lg`. The
engines are built once at import, because model load is the slow part
(`platform/packages/pii-gateway/src/pii_gateway/detectors.py:44-58`;
`platform/packages/pii-gateway/specs/001-pii-gateway/research.md` R1). Presidio's
packages don't bundle the model, so each environment installs it separately
(`platform/packages/pii-gateway/README.md:22-27`).

| Group | Categories | Backed by |
| --- | --- | --- |
| PII | `PERSON`, `EMAIL_ADDRESS`, `PHONE_NUMBER`, `LOCATION` | Presidio built-ins |
| PHI | `US_SSN`, `MEDICAL_LICENSE` | Presidio built-ins |
| PHI | `MEDICAL_RECORD_NUMBER`, `DIAGNOSIS_CODE` | First-party regex recognizers |

(`platform/packages/pii-gateway/src/pii_gateway/detectors.py:21-41`)

`LOCATION` also matches cities, countries and landmarks. The research accepted that as a
known false-positive source rather than build a narrower recognizer
(`platform/packages/pii-gateway/specs/001-pii-gateway/research.md` R1).

ADR-0043 rejected `sether` as an unaudited dependency in the PHI data path, `scrubadub`
for having no PHI recognizers, cloud DLP APIs because they send the content to another
third party, and regex alone because it under-detects free-text names
(`docs/adr/0043-pii-gateway-detector-library-presidio.md` §Alternatives considered).

## Failing closed

The spec requires a detector-engine error to be treated like a match, never a silent
pass-through
(`platform/packages/pii-gateway/specs/001-pii-gateway/spec.md` §Assumptions).
`_run_detectors` implements it by turning any exception into one synthetic
`_ENGINE_ERROR` result, which category config can't switch off
(`platform/packages/pii-gateway/src/pii_gateway/scrub.py:35-40`,
`platform/packages/pii-gateway/src/pii_gateway/scrub.py:47-53`;
`platform/packages/pii-gateway/specs/001-pii-gateway/research.md` R6).

That synthetic result is a zero-length span at offset 0. Redacting only the span is a
no-op -- `anonymize()` has nothing to replace at a zero-width location -- so `scrub()`
instead detects the synthetic match and replaces the **entire** input with
`<_ENGINE_ERROR>`, for both `redacted_and_proceeded` and flag-for-review's `REDACT`
resolution
(`platform/packages/pii-gateway/src/pii_gateway/scrub.py:81-89`). This is a 2026-11-05
bug fix: before it, a forced `RuntimeError` showed `"Contact Jane Doe"` under
`spec-generator` coming back as `<_ENGINE_ERROR>Contact Jane Doe` -- action
`redacted_and_proceeded`, content unredacted -- and the flag-for-review path's `REDACT`
resolved to the same no-op output
(`docs/adr/0046-pii-gateway-engine-error-fail-closed-semantics.md` §Context).

`Resolution.ALLOW` is rejected outright when the pending match is this synthetic case:
`PendingConfirmation.resolve()` raises `EngineErrorAllowRejected` rather than returning
the original text, enforced in the gateway itself so no caller can reach the
unexamined text via `ALLOW`. Nothing inspected the text, so there is no real detection
for the architect to judge and allow -- unlike `ALLOW` on a real match, which is
unaffected
(`platform/packages/pii-gateway/src/pii_gateway/models.py:20-30`,
`platform/packages/pii-gateway/src/pii_gateway/models.py:87-113`).
`modelling-specification`'s `resolve_pii` maps the exception to `409` and leaves the
pending confirmation in place, so `REDACT`/`EDIT` still resolve it and no LLM call is
made
(`platform/packages/modelling-specification/src/modelling_specification/router.py:440-447`).
The flag-for-review response also carries `detection_failed: bool` so a caller is told
detection failed outright, rather than left to infer it from the `_ENGINE_ERROR`
category string in `matches`
(`platform/packages/modelling-specification/src/modelling_specification/router.py:191-205`).

Both are recorded in ADR-0046, filed because the spec's fail-closed guarantee itself
was (and still is) a spec-level default with no ADR of its own -- this record covers
the redaction shape and the `ALLOW` question it exposed, not that wider gap
(`docs/adr/0046-pii-gateway-engine-error-fail-closed-semantics.md` §Decision;
`platform/packages/pii-gateway/specs/001-pii-gateway/spec.md` §Assumptions).

The browser authoring UI has a related, separately-tracked rough edge: its three
PII-review buttons (Redact/Allow/Edit) disable on click and only re-enable on a
successful `resolve-pii` response, so an `ALLOW` rejected under this path needed its
own re-enable path to stay usable. Since GH #186 (2026-11-08) the same click handler
also shows a "Thinking…" chat message while `resolve-pii` waits on the LLM, and
removes it in a `finally` whether the call returns, errors or throws
(`platform/packages/modelling-specification/src/modelling_specification/ui.py:692-716`).
See [Conversational Model Authoring](modelling-specification.md).

## Configuration and audit

Detector categories and the failure-mode are set per context in a local TOML file, read
on every call, so a change applies to the next `scrub()` with no restart. A missing file
means the ADR-0014 defaults
(`platform/packages/pii-gateway/src/pii_gateway/config.py:64-82`;
`platform/packages/pii-gateway/specs/001-pii-gateway/research.md` R4).

| | Default path | Override |
| --- | --- | --- |
| Config | `~/.config/frictionless-architect/pii-gateway.toml` | `PII_GATEWAY_CONFIG_PATH` |
| Audit log | `~/.local/state/frictionless-architect/pii-gateway-audit.jsonl` | `PII_GATEWAY_AUDIT_PATH` |

An override must resolve inside the home directory or the system temp directory, or it
raises `ValueError`. The check exists to answer the CWE-22 path traversal shape Snyk
Code flags (`platform/packages/pii-gateway/src/pii_gateway/_paths.py:1-45`).

Every call appends one JSON line holding the timestamp, context, distinct matched
categories and action. It never holds the matched text, locations or confidence
(`platform/packages/pii-gateway/src/pii_gateway/models.py:116-129`;
`platform/packages/pii-gateway/src/pii_gateway/audit.py:49-57`).

### Settings page

`create_settings_router(contexts)` serves an HTML page at `/settings/pii-gateway`, with
`GET .../state` and `PUT .../contexts/{context_id}` beneath it; an unknown context
returns 404
(`platform/packages/pii-gateway/src/pii_gateway/router.py:53-76`). It deliberately copies
the `llm-provider-config` router's shape
(`platform/packages/pii-gateway/specs/001-pii-gateway/research.md` R5).
[Portal](portal.md) mounts it for all three known contexts
(`platform/packages/portal/src/portal/app.py:13-14`,
`platform/packages/portal/src/portal/app.py:32`,
`platform/packages/portal/src/portal/app.py:40`). There is no authentication, so bind it
to localhost (`platform/packages/pii-gateway/README.md:63-65`).

## Where the sources disagree

- **PHI recognizer scope.** ADR-0043 expects custom recognizers for medical record
  numbers and provider/patient identifiers. The research and the code cover medical
  record and diagnosis codes, with no provider or patient identifier recognizer

  `platform/packages/pii-gateway/specs/001-pii-gateway/research.md` R2;
