## 001 — Frictionless Architecture & Governance Platform

**Status:** Draft — under rework. Created 2026-02-21; a "technology-agnostic
pass" landed 2026-08-28 and the branch was folded into `develop` for reference
during the architecture rework (`specs/001-governance-platform/spec.md:3-14`).
Requirements describe *what* the platform must do and *what properties* the
solution must have, never which product provides it.

### Deferred solution decisions

Choices deliberately removed from the spec so the rework can make them
intentionally (`specs/001-governance-platform/spec.md:27-38`): token/session
mechanism for auth, the authorization model and policy-rule language, the
crypto scheme and identity model for ADR attestation, accepted serialization
formats for model/interface ingestion, the wire format for structured API
errors, and the persistence technologies for the semantic model and platform
metadata.

### Functional requirements (FR-001 … FR-020)

Highlights (`specs/001-governance-platform/spec.md:114-154`):

- Maintain a machine-readable semantic model mapping technical components to
  data domains, CBS, and regulations (FR-001, FR-002).
- Ingest unstructured text for AI-assisted ADR drafting (FR-003) and **remove
  PII/PHI before any content reaches an external service** (FR-004).
- Produce ADRs linking each change to its rationale (FR-005); let a human
  architect apply a verifiable cryptographic attestation binding an ADR to an
  accountable identity (FR-006).
- Monitor for architectural drift (FR-007); provide a **Break-Glass** protocol
  with mandatory justification, logging, and automatic expiry — default 48h
  (FR-008, `spec.md:49`); raise a technical-debt record on "Managed Drift" (FR-009).
- Provide a queryable Regulatory Traceability Matrix (FR-010) and
  natural-language queries over the semantic model (FR-011).
- Map components to regulated CBS and their impact tolerances (FR-013); detect
  when a new decision contradicts an existing ADR (FR-014).
- Authenticate both humans and automated agents (FR-015); make authorization
  decisions in a **dedicated policy component** consuming verified identity
  attributes (FR-016).
- Protect data in transit and at rest (FR-017); periodically scan its own
  as-built state for threat modelling (FR-018).
- Keep all artifacts machine-readable (FR-019); automate enforcement of APRA
  CPS 230 and CPS 234 (FR-020).

### Priority journeys

P1 core governance (Break-Glass exception, ADR attestation, traceability-matrix
query); P2 specification lifecycle (developer initiates a spec, gets an
AI-drafted ADR); P3 platform operations (admin inspects KPIs)
(`specs/001-governance-platform/spec.md:41-108`). Edge cases cover an architect
refusing to attest, two conflicting ADRs, and a single consistent structured
error shape.

### Success criteria (provisional)

`specs/001-governance-platform/spec.md:181-191` — Mean Time to Compliance −30%
(SC-001); drift-detection accuracy > 98% (SC-002); Governance Friction
Coefficient −25% (SC-003); 100% of critical AI-drafted ADRs get a human
attestation before Approved (SC-005); traceability-matrix queries within
1 minute (SC-006); most model queries < 1s, complex < 5s (SC-007). All targets
are "provisional benchmarks carried from the original draft."

## 002 — Neo4j Schema Visualiser

**Status:** Draft. Created 2026-04-04. Single-user MVP that pairs every
ArchiMate node/relationship/view definition with curated sample data, serves it
over FastAPI, and keeps the schema summary usable when sample data or Neo4j is
unavailable (`specs/002-neo4j-schema-ui/plan.md:6-7`). Implemented — see
[Visualizer Service](visualizer-service.md).

### Clarified behaviour

`specs/002-neo4j-schema-ui/spec.md:10-16`: on missing sample data, show a
non-blocking warning banner but keep the element/relationship lists visible;
load responses within **2 seconds**, target **99.5%** availability; retry a
failed load within **5 minutes**; reuse the existing Neo4j read permissions
rather than adding an auth layer.

### Functional requirements (FR-001 … FR-007)

`specs/002-neo4j-schema-ui/spec.md:75-81`: summarise every node/relationship/view
type from `sample-data/schema` with names matching the schema exactly (FR-001);
pair each definition with at least one sample occurrence from
`sample-data/sample-00/Test Model.xml` including coordinates (FR-002); switch
between a diagram view (respecting stored `x/y/w/h`) and a tabular breakdown
(FR-003); show the source schema filename beside each type (FR-004); flag
schema types with no sample entry as coverage gaps (FR-005); non-blocking
warning when sample data is missing (FR-006); enforce the Neo4j read-permission
model (FR-007). Each FR cites Constitution principles VII–IX.

### Design decisions (research)

`specs/002-neo4j-schema-ui/research.md`: **cytoscape.js** + vanilla JS/HTML
tables for the UI (over D3 — too low-level; vis.js — larger bundle);
**`lxml` + `xmlschema`** to normalize the XSDs + `Test Model Full.xml` into a
shared JSON payload; reuse Neo4j read credentials from `.env` and fall back to
a cached JSON payload with a "Sample data unavailable" warning on outage.

> The **implemented** parser uses the stdlib `xml.etree.ElementTree`, not
> `lxml`/`xmlschema` (`src/frictionless_architect/visualizer/sample_parser.py:5`).
> The plan also names `Test Model Full.xml` as the sample source while the
> spec's acceptance tests reference `Test Model.xml`; config points at
> `Test Model Full.xml` (`src/frictionless_architect/visualizer/config.py:29`).

### API endpoints

From `specs/002-neo4j-schema-ui/contracts/api.md`, as implemented in
`src/frictionless_architect/visualizer/api.py`:

| Method & path | Purpose | Responses |
|---|---|---|
| `GET /schema-payload` | Aggregated model/element/relationship/view payload for both views. Query param `force_reload` (boolean, default `false`) bypasses the cache. | `200` with `{model, elements, relationships, views, warnings[], latency_ms}`; `503` when neither Neo4j nor sample data is available and no cache exists |
| `POST /schema-payload/refresh` | Kicks off an async cache rebuild; returns immediately. Optional body `{source}`. | `202` `{status: "refresh_started", estimated_completion_ms}`; `409` if a refresh is already running |
| `GET /schema-payload/status` | Cache freshness + connection state for the warning banner | `200` `{cache_age_seconds, neo4j_status, sample_file_status, last_warning, refresh_in_progress, ...}` |
| `GET /schema-visualizer` | Server-rendered HTML page (Jinja) that hosts the UI | `200` HTML |

`warnings` is always present (empty array when clean); `latency_ms` supports
the < 2s goal. The contract also documents `401/403` from Neo4j credential
rejection; the implementation surfaces those via the same cache-fallback path.

### Success criteria

`specs/002-neo4j-schema-ui/spec.md:94-100`: reviewers identify the backing
schema file within 2 minutes (SC-001); locate a sample element and its
relationships after one walkthrough (SC-002); diagram and table agree in ≥ 99%
of refreshes (SC-003); responses within 2s and ≥ 99.5% availability (SC-005);
5-minute retry with non-blocking warning on failure (SC-006); every request
respects Neo4j read permissions (SC-007).
