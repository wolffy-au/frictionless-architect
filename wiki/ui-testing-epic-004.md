EPIC-004 (GH #119, branch `feature/gh-119-playwright-ui-tests`) gives the platform's
server-rendered HTML UIs real browser-level smoke coverage that gates a merge. Its spec
is still marked **Draft** even though every task is ticked
(`specs/EPIC-004-playwright-ui-tests/spec.md` header; `specs/EPIC-004-playwright-ui-tests/tasks.md` T001–T017 all `[X]`).
The decision record is ADR-0053 (see
[Architecture Decision Log: ADR-0040 onward](decision-log-0040-onward.md)); the surrounding
test conventions live on [Development & Quickstart](development.md).

## Problem and scope

Before this work nothing exercised a page in a real browser: a change that loaded a page
with console errors, or broke its main interaction, could reach `main` unnoticed, because
existing tests only checked raw HTML payloads (`specs/EPIC-004-playwright-ui-tests/spec.md` §User Story 1). The merge gate also
carried a dead "frontend UI harness" step that looked for a `frontend/` directory that never
existed, printed "Skipping…" and always passed (`specs/EPIC-004-playwright-ui-tests/spec.md` §User Story 2).

Scope is exactly three surfaces named in GH #119: the control-conversion playground, the LLM
provider config page and the visualiser UI. Any later UI surface is follow-on work
(`specs/EPIC-004-playwright-ui-tests/spec.md` §Edge Cases, §Assumptions). "No console errors" plus "main interaction gives the
expected result" is deliberately the whole bar; deeper per-surface coverage is out of scope.

## Requirements in brief

| Area | Requirement |
|---|---|
| Coverage | A test per surface for load-without-console-error and main interaction (FR-001, FR-002) |
| Realism | Run against a live app instance, not a static fixture (FR-003) |
| Determinism | A deterministic stand-in where a backend needs an LLM or Neo4j (FR-004) |
| Gating | Excluded from the fast every-commit gate, run in the pre-merge gate (FR-005); the gate's UI step must execute the tests rather than skip (FR-006) |
| Docs | Local setup and run steps documented, including one-time environment setup (FR-007) |
| Flakiness | One automatic retry; a second consecutive failure is a real failure (FR-008) |
| Visualiser | Add a minimal placeholder page so there is something to test (FR-009) |

(`specs/EPIC-004-playwright-ui-tests/spec.md` §Functional Requirements.) Success criteria are all three surfaces passing at
least one test, a deliberately broken interaction being caught by the gate, the gate never
reporting "skipped", a documented from-scratch local run, and no impact on the fast gate's
runtime (`specs/EPIC-004-playwright-ui-tests/spec.md` §Success Criteria).

## Decisions

Three clarifications of 2026-11-14 shaped the plan (`specs/EPIC-004-playwright-ui-tests/spec.md` §Clarifications):

- **One retry, not fail-fast.** Chosen to cut flaky false positives, accepting a small risk
  of masking an intermittent real bug. `specs/EPIC-004-playwright-ui-tests/research.md` notes this diverges from the plan's own
  fail-fast default (Principle VII) and that the clarification is the binding decision.
- **Build a visualiser placeholder.** The visualiser serves only a JSON API; its real UI
  composition is tracked separately in still-open GH #74.
- **Extend the existing harness, no second toolchain.** The playground and LLM settings page
  already had `behave` + plain `playwright` coverage, so the proposed `pytest-playwright` was
  rejected as redundant (Principle I, DRY) (`specs/EPIC-004-playwright-ui-tests/research.md`).

Two further decisions: the dead `frontend/` block in `scripts/pre_merge_checks.sh` is deleted
outright, because `scripts/platform_checks.sh` and the existing root `behave tests/features/`
step already gate the work; and existing stand-ins are reused for external dependencies —
`FakeCompletion` for the LLM and the visualiser's sample-data fallback (the
`VisualizerSettings.neo4j_uri` default) for Neo4j (`specs/EPIC-004-playwright-ui-tests/research.md`).

## How the harness works

`specs/EPIC-004-playwright-ui-tests/plan.md` §Technical Context describes `behave` scenarios tagged `@ui`, each run against a
live `uvicorn` instance of the surface's real FastAPI app on an OS-assigned port in a
background thread, driven by headless Chromium through Playwright's sync API. Chromium only,
matching the harness being reused (Principle IX).

- **Root harness.** `tests/features/environment.py` gains a conditional live-server and
  Playwright setup in `before_scenario`/`after_scenario`, gated on the `@ui` tag so non-UI
  scenarios do not pay for a browser launch; the one-retry policy lives in the same hook
  (`specs/EPIC-004-playwright-ui-tests/tasks.md` T004, T009).
- **Platform packages.** `controls-compliance-catalog` and `modelling-specification` already
  carry the pattern; no changes were needed there (`specs/EPIC-004-playwright-ui-tests/plan.md` §Structure Decision). They are
  run by `scripts/platform_checks.sh`.
- **Dependencies.** `playwright` joins the root `pyproject.toml` `tests` group (T001–T002).
  CI installs Chromium before the root behave step (`.github/workflows/ci.yml`, per the
  `development` page), and `pre_merge_checks.sh` runs `poetry run playwright install
  --with-deps chromium` before its `behave` call (`specs/EPIC-004-playwright-ui-tests/tasks.md` T003).

## The visualiser placeholder page

`GET /` on the visualiser app returns `200 text/html`, renders without a console error, and
shows a value derived from the existing `/schema-payload` JSON endpoint — the sample-data
fallback when Neo4j is unavailable — which is the "main interaction" the smoke test asserts
(`specs/EPIC-004-playwright-ui-tests/contracts/visualiser-placeholder-page.md`). Its shape is a fixed title, status text and an
optional schema summary such as an element count; it has no stored state and no request
body (`specs/EPIC-004-playwright-ui-tests/data-model.md`). It is explicitly throwaway: superseded once GH #74 ships, not to
accrete features, and out of scope for authentication or styling. It lives in
`src/frictionless_architect/visualizer/` and is mounted in `src/frictionless_architect/app.py`
(`specs/EPIC-004-playwright-ui-tests/tasks.md` T005–T006). See [Visualizer Service](visualizer-service.md).

## Running it locally

One-time setup is `poetry run playwright install --with-deps chromium`, once at the root and
once inside `platform/`. Then `poetry run behave tests/features/ --tags=@ui` runs the root
scenarios, `bash scripts/platform_checks.sh` the platform ones, and
`bash scripts/pre_merge_checks.sh` the full merge gate. A failing scenario should name the
page and the error. The quickstart also describes how to prove the gate works: break one
page's interaction on a throwaway branch, confirm the gate fails and names it, then revert
(`specs/EPIC-004-playwright-ui-tests/quickstart.md`). `TECHNICAL.md` "Testing Layout" carries the setup notes and links to the
quickstart rather than repeating it (`specs/EPIC-004-playwright-ui-tests/tasks.md` T014); see
[Architecture Overview](architecture.md).

## Model impact

None. The plan reasons this out rather than assuming it: `playwright` sits in the `tests`
dependency group, which ADR-0044's Technology-layer threshold excludes, and unlike
`sw-pytest` (which hosts the OSCAL golden-check process) the `@ui` scenarios tie to no named
modelled `DataObject`. The placeholder is a capability of the existing `sub-schema-visualizer`
component and is deliberately short-lived; future real UI work belongs to the existing
`gap-neo4j-schema-ui` Gap (`specs/EPIC-004-playwright-ui-tests/plan.md` §Model impact). See
[Architecture Model](architecture-model.md).
